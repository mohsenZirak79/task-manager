# تغییر رمز عبور از تنظیمات حساب

`POST /api/v1/auth/password/change` با Bearer token کاربر واردشده و فعال در دسترس است؛ مجوز مدیریتی لازم ندارد و شناسه کاربر مقصد دریافت نمی‌کند.

فیلدهای اجباری: `current_password`، `password`، `password_confirmation`.
رمز جدید باید با رمز فعلی متفاوت، حداقل ۸ کاراکتر، شامل حرف/عدد/نماد و حداکثر ۷۲ بایت UTF-8 باشد. فاصله‌های رمز حذف نمی‌شوند.

- 200: رمز به‌صورت hash ذخیره شده؛ توکن فعلی باقی می‌ماند. سایر توکن‌های API و OTPهای استفاده‌نشده باطل می‌شوند؛ وضعیت `must_change_password` پاک می‌شود.
- 401: ورود لازم است؛ 403: حساب غیرفعال است.
- 422: خطاهای فیلدی، از جمله `current_password` اشتباه یا `password` نامعتبر.
- 429: حداکثر ۵ تلاش در دقیقه برای هر کاربر و ۲۰ تلاش برای هر IP.

این مسیر با بازیابی رمز OTP و تغییر رمز مدیریتی متفاوت است. هدف همیشه حساب احراز هویت‌شده است؛ فیلد اضافی `user_id` یا `identifier` حساب دیگری را تغییر نمی‌دهد. بررسی رمز فعلی، تغییر hash و لغو توکن‌ها/OTP در یک تراکنش و با قفل رکورد انجام می‌شود. خطا هیچ‌یک از این تغییرات را ثبت نمی‌کند. این سامانه از توکن API استفاده می‌کند؛ ادعای خروج از sessionهای جداگانهٔ cookie-based مطرح نیست.

در فرانت، گزینه «تغییر رمز عبور» در منوی عکس کاربر، زیر «پروفایل من» قرار دارد و فرم در مودال باز می‌شود، نه در صفحه تنظیمات. فرم از Axios Client و React Query موجود استفاده می‌کند؛ عملیات نوشتن retry خودکار ندارد، هنگام ارسال قفل می‌شود، پس از موفقیت فیلدها خالی و کش پروفایل تازه می‌شود و مودال بسته می‌شود. هنگام درخواست، بستن مودال غیرفعال است؛ با بستن عادی، فرم از درخت حذف می‌شود و اطلاعات واردشده در بازکردن مجدد باقی نمی‌ماند. رمز در storage ذخیره نمی‌شود و وضعیت mutation بعد از پاسخ reset می‌شود. روی خطای اعتبارسنجی، فیلد مربوط مشخص و متن واردشده برای اصلاح حفظ می‌شود.

تست‌های بک‌اند با SQLite موقت انجام می‌شوند و رمز هیچ کاربر Production برای تست تغییر نمی‌کند. افزودن قابلیت به migration جدید نیاز ندارد. استقرار نیازمند انتشار هم‌زمان فرانت و بک‌اند و تازه‌کردن route cache، در صورت استفاده، است.

## نتیجه بررسی ۲۰۲۶/۱۰/۲۲

- تست اختصاصی بک‌اند: ۶ تست و ۵۹ assertion موفق؛ شامل حفظ توکن فعلی، لغو توکن‌های دیگر/OTP، حساب غیرفعال، محدودسازی تلاش، رمز اشتباه، محدودیت طول بایتی و حفظ فاصله‌ها.
- فرانت: ۲۳۲ تست موفق، Lint و Build موفق. تست جدید از MockAdapter، schema واقعی، hook واقعی React Query و رندر واقعی فرم استفاده می‌کند.
- قالب‌بندی PHP با Pint و بررسی `git diff --check` موفق.
- تست کامل بک‌اند: ۱۴۷ موفق، ۹ شکست، ۸ خطا و ۲ skipped. اجرای همان مجموعه از کامیت قبلی در مسیر موقت جدا، همان ۹ شکست و ۸ خطا را نشان داد (۱۴۱ موفق). نام تست‌های ناموفق دقیقاً یکسان است؛ خطای جدید ناشی از این قابلیت دیده نشد. ایرادهای قدیمی بخش نقش‌ها/کاربران خارج از این تغییر حفظ شدند و هیچ تستی حذف نشده است.
- در تست‌های خودکار، هیچ رمز واقعی روی سرور برای آزمایش تغییر نمی‌کند. برای انتقال رمز در محیط واقعی باید HTTPS استفاده شود.
